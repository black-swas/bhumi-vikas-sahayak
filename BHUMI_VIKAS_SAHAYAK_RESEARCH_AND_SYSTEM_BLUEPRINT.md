## 1. The problem, restated from the brief

- **User:** a Bhopal Municipal Corporation building-permission clerk at the counter, with a citizen waiting.
- **Their question (verbatim from the guide):** "My plot is 200 sq m on a 9 m road. How much gap do I leave at the front, how many floors can I build, and what fee do I pay?"
- **Need:** a correct answer within a minute, with the rule number to show the citizen. The tool points to the rule; the clerk decides.
- **Hard parts named by the brief:** table numbers are easy to misread; the rules change (consolidated copy stops 06/03/2025; Rule 2(5)(c) changed 28/08/2026); questions arrive in English and Hindi while the Hindi PDF copies out as garbage.

### Why a plain LLM + vector-RAG chatbot fails here
1. **Band boundaries.** "Up to 9.0 m" versus "more than 9.0 m and up to 12 m" is exactly the kind of cut-off models get wrong. Hence code, not the model, does lookups.
2. **Invented citations.** The book ends at Rule 105 (plus 26-B). Any "Rule 150" is a fabrication, so every citation is checked against the text.
3. **The floors trap.** The rules contain no maximum number of floors. Capacity comes from FAR (Rule 61), height (Rule 56 up to 12.5 m; Rule 42 and Rule 65 above) and the Development Plan (Rule 103). A model will guess "G+2". The tool must say the rules don't give a floor count and show what they do give.
4. **Language.** The Hindi PDF is in the legacy Kruti Dev font (`fu;e 56` is नियम 56). Its pagination matches the English PDF, so we link to it rather than parse it.
5. **Version drift.** The pack's text stops at 06/03/2025. The 28/08/2026 amendment is known only from a secondary summary with no notification number or verbatim text, so it is shown as a caveat, never as a quote.

## 4. Frontend base: OpenHands Agent Canvas, and Vercel

Added in revision 2, after `OpenHands-main/` was dropped into the workspace. The design that follows from this section is `SPEC.md` §16 and §16A.

### 4.1 What it is (checked in the folder)

`@openhands/agent-canvas` v1.26.0, MIT licence. A control centre for coding agents: React 19, React Router 7 as a single-page app (`ssr: false`), Vite 8, Tailwind 4, HeroUI. It has 1,540 source files, 2,808 translation keys in 15 locales (**no Hindi**), a Vercel preset already wired into `react-router.config.ts`, and it needs Node 24 or later.

### 4.2 Assessment

| | Finding | Consequence |
|---|---|---|
| **Fits** | The rail + thread + resizable side panel is the same shape as our question → Answer Card → evidence | Reuse the layout (SPEC §16.2) |
| **Fits** | Token-based theming (`--oh-*` variables) with a light theme, plus accessibility and i18n lint rules, MSW mock mode, vitest, and the Vercel preset | Reuse the look and the toolchain |
| **Doesn't fit** | The root layout chains every query off an Agent Server (`/server_info`); with no backend it can't render | Never run the app as is: import by whitelist |
| **Doesn't fit** | Bundles a terminal (xterm), a code editor (Monaco) and agent screens a clerk never uses; heavy for a low-bandwidth counter PC | Drop them |
| **Risk (privacy)** | Ships PostHog telemetry. Clerk questions must not reach a third-party analytics service | Remove it; a grep check before FREEZE |
| **Risk (offline)** | `index.css` imports **Google Fonts from a CDN**: fails on an offline counter PC and leaks the clerk's IP | Self-host with `@fontsource`, including Noto Sans Devanagari |
| **Risk (output handling)** | Includes `react-markdown` with `rehype-raw`, a path for HTML injection if model text were rendered | Drop both; plain text only |
| **Gap** | No Hindi locale | Add `hi`, drop the other 14, and let the completeness check enforce parity |
| **Gap** | Dark by default | Default to its light theme for office lighting |
| **Rules** | The brief says code must be written from 10:15, and the playbook says to ask before reusing pre-event code | Ask at the briefing (SPEC §26 #9); fallback is HeroUI + Tailwind with no copied file |
| **Branding** | OpenHands name and logo | Remove from the UI; keep the MIT notice in `THIRD_PARTY_NOTICES.md` |

**Alternatives considered:** (a) fork the whole app and mock its backend: rejected, 1,540 files with hidden coupling is a bad trade for one day; (b) build from scratch on HeroUI: kept as the fallback if reuse isn't allowed; (c) the static HTML page from the first spec: rejected, because it gives up themes, i18n, tests and the UX the request asked for.

### 4.3 Vercel (from Vercel's docs, 11 Oct 2026)

- A FastAPI app named `app` is detected at `app/main.py` and runs as a Vercel Function. Python 3.12 is the default, matching our pin. The bundle limit is 500 MB; ours is well under 1 MB.
- **Services (Beta)** puts a frontend and a Python backend in one project on one domain, with top-level rewrites (`/api/*` → backend, everything else → frontend). The service receives the original path, so our routes are declared under `/api`. Because it is Beta, the spec carries Plan B (two projects and an external rewrite) and Plan C (local only), with a 20-minute time-box.
- **What a function platform changes in the design:** the backend must be stateless (no runtime writes, so audit goes to stdout and the replay cache is committed read-only); the rate limiter is per instance; the first call after idle is a cold start; paths resolve from `__file__`; the default region is `iad1`, far from Bhopal, so latency is measured, not assumed.
- **What it doesn't change:** the counter-PC offline claim is about the **local** run. A hosted copy is online by definition, so it is a convenience for the jury, never the only path.
- **New open questions:** who owns the Vercel project, whether Services is enabled for it, and whether sending clerk questions through Vercel and Cerebras (both outside India) is acceptable (SPEC §26 #10–#12).

### 4.5 Consumer mode and admin mode (revision 3)

The first two revisions had no accounts and no admin, which is right for the brief ("one workflow, one user, one outcome. Don't build a portal"). Admin mode was added on request, so it is designed to stay small and optional (`SPEC.md` §16B).

- **Why it earns a place at all:** the problem statement's hard part is that the rules keep changing. An amendment registry lets a maintainer publish a warning without a redeploy, and a review queue turns a clerk's "this answer is wrong" into a regression case. Both feed the day-one-impact criterion.
- **What it must not become:** a general portal, or a way to alter the rulebook. No role can edit the corpus, tables, calculators or verification checks, see a key, or pick a model off the allowlist.
- **Roles:** consumer (anonymous), then staff viewer, editor and admin, with fifteen named permissions enforced on the server and a route-walking test that fails if any route lacks one.
- **Cost of the choice:** the stateless backend now needs a store (SQLite locally, a Marketplace Postgres on Vercel), and a counter PC's store is separate from the hosted one, so a snapshot export and import bridges them (tier A3).
- **Cut line:** if the consumer app isn't green by 14:30, admin mode is dropped and amendments stay in the committed JSON.
